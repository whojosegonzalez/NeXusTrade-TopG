## Dependency inventory and exceptions

The TypeScript resolver inventory covers 595 source modules. It records static runtime/type imports and re-exports; dynamic loaders are capability findings. `node scripts/architecture-check.mjs --inventory` emits the full graph without running application modules. The checked-in inventory enumerates 51 admitted test files, their source closures and setups, and 100 excluded test files with admission prerequisites. New tests outside the four harnesses are not automatically admitted. Changes inside the existing H1/H3/H4 owned test globs still require review of their I/O and fixture dependencies.

`architecture-policy.json` lists exact runtime and type targets for each protected group. The three schema type imports from `drizzle-orm/sqlite-core` use exact source/specifier permissions plus resolved external package identity and worktree containment; physical pnpm peer-suffix paths are not portable policy identifiers. Runtime closure is traversed anew on every check; newly imported modules, unresolved targets, redirected source, dynamic loaders and prohibited globals fail. Type-only edges are checked separately and do not execute or recursively expand the referenced type module. The installed TypeScript resolver handles local aliases. Configuration/harness entrypoints are separately compiled and audited, not exempted by a generic test-folder rule.

## Test admission and fixture audit

H1 retains its five synthetic analyzer suites and path/API mutation tests. H2 retains 22 audited accounting/schema suites and its guarded SQLite factory. H3 retains 20 provider suites with injected transports, clocks and budget/concurrency fixtures. H4 admits only AnalyticsReportService.test.ts and the three H4 test files; two Node test files cover checker/runner failures. Exact filenames and statically visible source dependencies are in the inventory; third-party test tools are locked installation dependencies, not recursively audited source.

H4 service tests construct repositories against `createTestDatabase`, intercepted by H4 setup to use unchanged `createH2TestDatabase`. That helper creates uniquely owned `.tmp/h2/sqlite-*` fixtures, applies migrations only there and verifies ownership before cleanup. H4 source/graph fixtures use `.tmp/h4`; caches and runner temporary environment stay under this worktree. H4 setup rejects default SQLite paths, env/archive reads and reachable fetch/http/https/net/subprocess APIs. Static fixture dependencies include the original helper because mocks refer to it, but the admitted runtime uses the guarded replacement. No analytics CLI/bootstrap is executed.

`DashboardExportService.test.ts` specifically reads historical operational archives/databases and writes frontend public output; it remains excluded. The other 99 omitted tests have not been admitted by this audit and must have their transitive transports, env/default DB, fixture roots and cleanup reviewed before expansion. Legacy `pnpm verify` and blanket `pnpm test` are **not** the isolated verification workflow. The guarded suites are scoped regression evidence, not full repository test coverage or an OS sandbox.

## Read facade and projections

The facade admits sessions.getSessionById/listSessions, tokenRadar.listRadarEntries, riskAssessments.listRiskAssessments, strategyDecisions.listStrategyDecisions, orders.listOrders, fills.listFillsForSession, positions.listOpenPositions/listClosedPositions, snapshots.listEquitySnapshots, watchlistReturns.listObservations, and providerHealth.listProviderHealth. Calls retain the original order; row-limited report queries use 10,000, latest-session search uses 100 PAPER sessions and one-row radar/decision probes. Provider history uses the fixed report clock minus configured provider hours. Explicit session selection, latest populated selection and missing-session failure are tested. Runtime proxies reject unlisted repository access; compile-negative fixtures reject mutations/raw DB and repository input to the calculator.

Row fields retain their schema record types at the service boundary. Pure quote facts contain only selected, selectionReason, rank, candidateSignals and buyQuoteObserved. Strategy projections contain symbol, riskResult, riskFlags, blockingFactors, liquidityUsd, volume1hUsd, ageSeconds and maxPriceImpactPct. The service still computes its other metrics from unchanged typed rows.

| Persisted producer                                        | Stored input → reader                           | Contract                                                                                                                                                               |
| --------------------------------------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| strategy/StrategyEvaluationService.ts, buildInputSnapshot | inputSnapshotJson → readStrategyProjection      | API-selected legacy v0; no persisted tag/writer change. Preserve finite numbers, financial strings, partial optional fields, filtered arrays and factor-name fallback. |
| risk/RiskAssessmentWriter.ts, summarizeRiskEvidence       | rawProviderDataJson → readQuoteBudgetProjection | v0 requires boolean selected and nonblank selectionReason; malformed optional rank/signals/enrichment preserve usable evidence.                                        |

Synthetic service fixtures and two snapshots were recorded against the original implementation before refactoring. Reader outcomes are bounded `OK`, `MISSING`, `MALFORMED_JSON`, `INVALID_FIELDS`, `UNSUPPORTED_VERSION`; they do not echo raw input. Unrelated fields are ignored as before. No backfill, envelope, migration, global parseJson change or report-column change was introduced.

## Deferred reader debt

The inventory lists every source consumer importing the legacy db/utils/json helper. ProviderPressureClassifier, StrategyScoringService, watchlist, shadow, enrichment, calibration and truthing projections retain their local validation/fallback contracts; H4 does not certify them as versioned readers. MeasurementCohortArchiveService's generic manifest/source/lock parsing remains frozen debt owned by the cohort maintainer. The B.3 loader and exploratory loaders have separate explicit validation and must not be conflated with generic casts. PaperOperationRepository retains H2's validated intent/result contract. Any future writer version or archived-reader change needs its own compatibility and provenance review.
